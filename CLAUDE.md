# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Proyecto

OneBook (antes OneLearn): sitio estático en español (es-MX) publicado con GitHub Pages en `https://chucho-rey.github.io/OneLearn/` (rama `main`; el repositorio y la dirección conservan el nombre viejo por ahora). Es un espacio de trabajo de **bloques y plantillas** para **empresas** (ventas, cobros, inventario, gastos, recursos humanos); todo se guarda solo en el navegador. Local es gratis; la nube será de pago (F9). Todo el texto de la interfaz, los comentarios del código y los mensajes de commit van en español. El plan, las características y el roadmap viven en Notion (página «OneBook», con «OneBook: plan para pivotear» y la base «Roadmap», área OneBook): es la fuente de información del equipo; al terminar un hito, actualiza ahí su estado. Hechas: F1 a F7 (F3 pestañas, F4 bloques de la tienda, F5 plantillas, favoritas y papelera, sin páginas dentro de páginas a propósito, F6 bases de datos, F7 inventario, reportes y «Mi negocio»), recursos humanos, Ayuda, historial de versiones y explorador con permisos. En curso, la etapa **Empresas** (decisiones en la sección 0 del plan): E1 separar lo académico (hecha), E2 empresa, personas y departamentos, E3 salas por departamento, E4 Inicio armable, E5 bienvenida para empresas; después, historial de filas, F8 pedidos al Cedis (con sucursales), F9 cuentas y nube. Decisiones vigentes: local primero, solo MXN, una empresa por espacio. Lo académico (lecciones, rutas, proyectos, terminal, libretas, apuntes, tesis) salió en E1 y vive en la historia de git (último commit con todo: `b0e99c5`); los datos de quien lo usaba se conservan (ver «Lo de estudio que se separó»). Las claves internas conservan el nombre viejo a propósito (prefijo `aprende-tecnologia:`, base `onelearn`, cachés `onelearn-`): cambiarlas borraría los datos de quien ya usa la app. Los respaldos se escriben con `app:'OneBook'` y se aceptan también los de `app:'OneLearn'`. El `README.md` describe el estado técnico actual.

## Comandos

No hay paso de compilación para publicar: se abre `index.html` o se sirve la carpeta con cualquier servidor estático. `index.html` es la página de bienvenida (landing) y el Inicio de la app es `inicio.html`; las pruebas entran por `inicio.html`.

Pruebas (Playwright, en `pruebas/`):

```
cd pruebas
npm install && npx playwright install chromium   # la primera vez, en una máquina propia
npm test                      # todas (node todas.js)
node todas.js 3 24            # solo los archivos 3-*.js y 24-*.js
node 9-editor.js              # un solo archivo
DETALLE=1 node 2-lectura.js   # muestra también lo que pasa
```

En el contenedor de Claude Code, Playwright está instalado globalmente: anteponer `NODE_PATH=/opt/node-tools/node_modules`. La suite completa tarda unos 4 minutos; conviene correrla en segundo plano.

Tiptap (solo al cambiar su versión): `cd herramientas/tiptap && npm install && npm run compilar` regenera `assets/vendor/tiptap.min.js` y `tiptap-LICENSE.txt`. Las versiones están fijadas en su `package.json`. docx y Paged.js (imprimir o exportar): `cd herramientas/exportar && npm install && npm run copiar` regenera `assets/vendor/docx.min.js` (solo lo que importa `entrada.js`), `paged.min.js` y `exportar-LICENSE.txt`.

## Arquitectura

- **Scripts clásicos con un espacio global `window.AT`**, sin módulos ES ni bundler (para que funcione con `file://`). El orden de los `<script>` importa y está documentado en el README; cada página (`index.html`, `inicio.html`, `documento.html`, `ayuda.html`…) lista los suyos. `ajustes.js` va en el `<head>` y aplica tema, contraste, tamaño, etc. antes de pintar.
- **Formato de bloques** (`assets/js/bloques.js`): las páginas (y la Ayuda) son el mismo JSON `{formato, tipo, id, titulo, icono, props, contenido}`, donde `contenido` es JSON de Tiptap/ProseMirror. Cada bloque de primer nivel tiene `attrs.id` fijo (ancla de enlaces y de la búsqueda). `bloques.js` lo dibuja sin `innerHTML` con datos del documento y filtra enlaces (`hrefSeguro`). El editor (`editor.js`) define los mismos tipos de bloque como nodos de Tiptap; un tipo nuevo debe agregarse en ambos lados (y en el Markdown de `documento.js` y el texto de `bloques.js`). **Nada se pierde**: el editor envuelve todo nodo que no conoce (o que no cuadra con el esquema) en `legado`/`legadoLinea` con el JSON original en `attrs.json`, y `desenvolver` lo devuelve idéntico en `json()`, al guardar y en `guardarYa`; al leer, `AT.bloques.LEGADO` da el nombre de los tipos que se quitaron. Si quitas un tipo de bloque, agrégalo a `LEGADO`.
- **Lo de estudio que se separó** (etapa E1): `AT.datos.deEstudio(doc)` (tipos libreta, clase, libro, investigacion, tesis, guia, bitacora) esconde esas páginas de la barra, la búsqueda y el explorador (salvo la ubicación «De estudio (solo lectura)»), y `documento.js` las abre solo para leer, con aviso, «Imprimir o exportar» y Markdown (sus `fuentes` y `autoria` quedan intactas). `perfil.js` convierte los perfiles `estudio` y `personal` en `negocio` con `aviso` (el Inicio lo explica una vez: `AT.perfil.aviso`/`quitarAviso`). Las notas de las lecciones, marcadores, avance, proyectos y ejercicios de la terminal siguen en los datos y en el respaldo. Las citas de antes a lecciones, proyectos, rutas o acerca se dibujan como texto. Prueba: `38-sin-estudio.js` (también revisa que lo de estudio ya no se publique).
- **Piezas e imprimir o exportar** (`piezas.js`, `exportar.js`, `imprimir.html`/`imprimir.js`, `exportar-docx.js`): `piezas.js` agrega la imagen comprimida (`figura`, con pie y texto alternativo), la tabla numerada, las notas al pie y las referencias cruzadas; registra sus nodos con `AT.editorExtensiones`/`AT.editorInsertar`, su dibujo con `AT.bloques.registrar` y su Markdown con `AT.piezas.md`, sin tocar editor.js ni bloques.js. Las tablas llevan `attrs.clave` única (la cuida el plugin de ids), destino de `refCruzada`. «⋯ › Imprimir o exportar» (`AT.exportar.dialogo`) guarda el papel en `doc.formato` ({papel carta|a4, orientacion vertical|horizontal}) y ofrece PDF (`imprimir.html`, Paged.js; la hoja del papel se arma en JS y los números de página se fijan página por página) y Word (`AT.exportarDocx`, con el paquete docx; estilo `LeyendaTabla`). Pruebas: `18-piezas.js` y `20-exportar.js` (revisa el DOCX abriendo el ZIP con zlib).
- **Bloques de la tienda** (fase F4: `negocio.js` + `caja.js` corte de caja, `fiado.js`, `gastos.js` con «Generar mes», `venta.js` nota de venta con folio, `precio.js` calculadora de precio (también en `index.html`) y `porpagar.js` cuentas por pagar; se cargan después de `pagos.js` en documento.html e imprimir.html): un bloque nuevo se define con `AT.negocio.bloque(nombre, {etiqueta, def, filas, editar, resultado, leer, refrescar, acciones, texto, md, insertar, foco})`, que registra el nodo de Tiptap (atómico, un atributo JSON por clave de `def`), su dibujo, texto y Markdown, y su entrada en «/» con `modulo:'negocio'`; agrega el tipo a `AT.editorConId`. El HTML de `editar`/`leer` enlaza campos con `data-k="ruta.de.campo"` (`data-fecha` en casillas guarda la fecha; `data-repintar` repinta al cambiar) y botones con `data-acc` (`agregar`/`quitar` con `data-lista`/`data-i` ya existen; `data-enter` en un campo dispara una acción). `filas` da la forma de cada fila y no debe usar datos al azar (también completa lo guardado). Dinero: `AT.negocio.centavos`, `dinero(c, signo)` y `monto(c, signo)` (negativos con «−» y `.neg` en rojo). Folios: `AT.folio(prefijo)` en base.js (`aprende-tecnologia:folios`, entra en el respaldo). Estilos: lectura y formulario (`.nb-f`) en `negocio.css`, papel en `imprimir.js`. En las pruebas, Tiptap enfoca en el siguiente cuadro: espera el foco en `.ProseMirror` antes de teclear. Prueba: `24-tienda.js`.
- **Plantillas, favoritas y papelera** (fase F5; no hay páginas dentro de páginas, a propósito): `crear.js` es la galería (cada tipo de `AT.tiposDoc` tiene `cat` general|negocio|rh y `trae`; `PAQUETES` por giro; «Mis plantillas» en `AT.datos.plantillas`). `AT.crear.guardarPlantilla(doc, {nombre, desc, vaciar})` usa `VACIAR` por tipo de bloque y `desdePlantilla` usa `AL_CREAR` (fecha, folio, mes): un bloque nuevo con datos del día o anotados debe agregarse ahí. `datos.js` va en la versión 2 de la base con los almacenes `plantillas` (en el respaldo) y `papelera` (`AT.datos.papelera`: mover, restaurar, eliminar, vaciar; 30 días). Favorita: `doc.favorito`, se guarda con `conservarFecha`. Papelera en `respaldo.js` (`AT.papelera.abrir`, `[data-papelera]`). Inicio: acciones rápidas con `documento.html#agregar=<bloque>` (evento `onebook:agregar`, lo atiende `negocio.js`) y «Prepara tu negocio» (`aprende-tecnologia:prepara`). Prueba: `25-plantillas.js`.
- **Bases de datos** (fase F6: `bases.js` motor sin interfaz, `basedatos.js` el bloque, `bases.css`; en documento.html e imprimir.html después de `porpagar.js`): base `{id, nombre, doc, columnas, vistas}` y fila `{id, base, v:{idColumna: valor}, orden}` en los almacenes `bases` y `filas` (índice `base`; `AT.datos.filas.deBase`), versión 3 de la base. `AT.bases` guarda en memoria lo leído (`cargar` trae también las bases relacionadas), calcula (`valor`, `texto`, fórmulas con `compilar`, sin eval), filtra, ordena, agrupa, totaliza, lee y escribe CSV, y avisa los cambios (`AT.bases.on`; entre pestañas, por `AT.datos.on`). Tipos y su forma en el README; la primera columna es el nombre. El bloque `basedatos` guarda `{base, vista}` o `{semilla}` (plantillas, duplicar, tus plantillas): la base se crea al abrirlo (`AT.bases.crear`, una vez por bloque). `imprimir.js` llama `AT.bases.precargar` antes de paginar. El importador de Bases unificadas está en `datos.js` (`importar` con `app:'bases-unificadas'`). En las pruebas, un elemento `.vh` dentro de una tabla con scroll necesita un ancestro posicionado (`.bd-scroll` lo es). Prueba: `26-bases.js`.
- **Inventario, reportes y «Mi negocio»** (fase F7; `inventario.js`, `factura.js`, `reporte.js`, `indicadores.js`, en documento.html, imprimir.html e inicio.html después de `basedatos.js`): bases con `rol` (productos, movimientos, compras, gastos, presupuesto), una por espacio: `AT.inventario.asegurar(doc, roles)` las busca o crea (ids de columna fijos: `p-*`, `m-*`, `c-*`, `g-*`, `r-*`; el resto del código los usa) y `base(rol)` es lo que usa un bloque `basedatos` con `semilla:{rol, vista}`. La nota de venta (`venta.js`) liga conceptos a productos (`prod`) y `inventario.js` sincroniza sus movimientos «Venta» al guardarse una página (`AT.datos.on`, `m-origen` venta:<página>:<bloque>:<i>), los quita antes de la papelera (`documento.js`) y concilia todo al abrir. Fórmulas con comparaciones, texto y funciones en `bases.js` (`compilar` da `fn.tipo` numero|texto|logico); formato condicional `col.colores` y `B.tonoCelda`. Bloques propios con nodo de Tiptap (atributo `cfg` JSON): `reporte` (cfg con `base` o `rol`, `pbase` o `prol` para presupuesto; `AT.reporte.calcular`), `indicadores` (items de reporte) y `vencimientos` (dias); en el Inicio se dibujan vivos (`data-pagina` inicio) y al imprimir como papel. Lo que un bloque necesita leído antes de imprimir va en `AT.bases.precargas`. Para abrir una ventana desde un clic dentro de un bloque usa `setTimeout` (quien cierra ventanas al hacer clic fuera la cerraría). Imprimir acepta hoja horizontal (`doc.formato.orientacion`). Inicio de negocio: «Mi negocio» = documento `d-minegocio` (se crea solo una vez, solo si `AT.datos.documentos.leer` no lo encuentra). Pruebas: `28-inventario.js`, `29-reportes.js`, `30-indicadores.js`, `31-minegocio.js` (espera «Guardado» antes de recargar una página que acabas de cambiar).
- **Recursos humanos** (módulo `rh` de perfil.js; `nomina.js` motor sin interfaz con las cifras de 2026 en `AT.nomina.T`: actualízalas cada año (UMA en febrero, salario mínimo en enero, tarifa del ISR y subsidio si cambian); `rh.js` calculadoras con `AT.negocio.bloque(..., {modulo:'rh'})`; `equipo.js` bloques `equipo` y `planilla` que leen las bases con rol `empleados` (`em-*`) e `incidencias` (`in-*`) de `inventario.js`; en documento.html, imprimir.html e inicio.html): el Inicio de un negocio con rh muestra «Tu equipo» (`d-miequipo`, igual que «Mi negocio»: `PAGINAS_INI` en inicio.js) y las acciones rápidas `ACCIONES.rh`. Plantillas con `cat:'rh'` en crear.js; «Tengo empleados» (`#enRh`) en entrar.html. Pruebas: `33-rh.js` (motor y calculadoras) y `34-equipo.js` (módulo, equipo, nómina del equipo, Inicio).
- **Plan de pagos** (`pagos.js`, bloque `pagos` en cualquier documento; estilos de lectura en `negocio.css`; `AT.pagos.vista(attrs, {editable, marcar})` dibuja la vista de lectura): `attrs` {titulo, modo plazos|cuota, monto, pagos, cuota, frecuencia, inicio, pagados:{n: fecha}}; `AT.pagos.calcular` trabaja en centavos y el último pago absorbe el redondeo. Al leer, marcar un pago cambia el bloque en `AT.docActual` (por su `attrs.id`) y guarda con `AT.docCambio`. Prueba: `21-pagos.js`.
- **Datos** (`datos.js`, `AT.datos`): documentos, tus plantillas, la papelera, bases y filas, el historial de versiones y lo de estudio que quedó (notas de las lecciones y marcadores) en IndexedDB (base `onelearn`, versión 4), con `localStorage` como respaldo si no hay IndexedDB. Si quedó alguna nota en el diario de `localStorage` (`aprende-tecnologia:apuntes:<id>`), se pasa a IndexedDB al cargar. Ajustes, perfil, folios y quién eres siguen en `localStorage` (prefijo `aprende-tecnologia:`). Los cambios se avisan con `AT.datos.on` y entre pestañas con BroadcastChannel.
- **Historial de versiones** (`datos.js` `AT.datos.versiones`, base versión 4 con `versiones` e índice `doc` y `trozos`; `versiones.js` + `versiones.css` en documento.html; `AT.docVersiones` en documento.js): versiones por bloques con huellas y trozos compartidos (sin cadenas de cambios: cada versión se lee directo). `documento.js` llama `abrir` al cargar, `observar` después de cada guardado (una cada 5 min y la de antes de un borrado grande) y `tomar` al salir; `importar` guarda la de antes y `papelera.eliminar` borra el historial. Lo que no es contenido va en el trozo «meta» (`FUERA_META` excluye id, fechas, favorita, ancho y autoría). Si un bloque nuevo guarda datos fuera de `contenido`, revisa `FUERA_META` y `CONSERVAR` en documento.js. En las pruebas, `AT.datos.versiones.config.ventana=0` guarda una versión en cada cambio. Prueba: `36-versiones.js`.
- **Explorador y permisos** (`explorador.js` + `explorador.css` en inicio.html, clases `xp-*`; `permisos.js` + `permisos.css` en inicio.html y documento.html; modelo en `datos.js`: `AT.datos.yo`, `AT.datos.acceso` sobre `doc.acceso`, `AT.datos.presencia`): «Tus páginas» del Inicio es un explorador (inicio.js le pasa las páginas con `AT.explorador.datos`). Roles: dueno, admin, editor, lector (y `ninguno` si no estás en la lista); `acceso.puede(doc, 'editar'|'compartir')` decide qué se ve y qué se hace (documento.js abre para leer sin permiso de editar). Cambia los permisos siempre con `AT.datos.acceso` (lee lo último y guarda con su propia fecha `acceso.cambio`), nunca escribiendo `doc.acceso` a mano. `acceso` y `editadoPor` están en `FUERA_META` (historial) y `CONSERVAR` (restaurar). Prueba: `37-explorador.js` (incluye el recorrido entre dos personas con respaldos).
- **Ayuda** (`ayuda.html`, `data-pagina="ayuda"`, `ayuda.js`, `ayuda.css`; se genera con `python3 herramientas/ayuda/generar.py`: edita ahí las secciones): la guía de usuario en el formato de bloques; cada herramienta es un `heading` de nivel 2 con id `ay-<módulo>-<nombre>` (módulo núcleo, negocio o rh: ayuda.js filtra por el perfil) y `PLANTILLA` en ayuda.js liga la sección con su plantilla de crear.js. **Al agregar una función visible, agrega o actualiza su sección.** Está en `PAGINAS` de buscar.js con `siempre:true` (se busca en cualquier espacio). Prueba: `35-ayuda.js`.
- **Pestañas** (`app.html`, `pestanas.js`, `pestanas.css`, fase F3): el contenedor pone cada página en un iframe; `base.js` (si `window.parent.AT.pestanas` existe) marca `AT.enPestana`/`.en-pestanas`, avisa título y dirección (`AT.pestanas.cambio`), pasa atajos (`AT.pestanas.atajo`) y abre en pestaña nueva los enlaces con clic central o Ctrl/Cmd+clic. `AT.pestanas`: abrir, abrible, cerrar, activar, descargar, lista. `app.html` es el `start_url` del manifiesto y no se abre dentro de sí mismo. `documento.js`: `AT.docGuardarYa` (lo usa el contenedor antes de cerrar o descargar) y el bloqueo de la misma página en dos pestañas (`onebook-documentos`). Botón Atrás: `AT.alAtras(fn)` (CloseWatcher) para paneles que no son `<dialog>`. Prueba: `23-pestanas.js` (para elementos dentro de una pestaña oculta, `waitForSelector` con `state:'attached'`).
- **Perfiles y módulos** (`perfil.js` en el `<head>` de todas las páginas después de `ajustes.js`, `entrar.html`/`entrar.js`/`entrar.css`, fase F2): `AT.perfil` con `aprende-tecnologia:perfil` = {perfil negocio, modulos, nombre, negocio:{nombre, giro, telefono}, creado, migrado, aviso}. `AT.perfil.tiene(modulo)` decide qué se ve (sin perfil, todo). Módulos: `negocio` (plan de pagos, bloques de la tienda y plantillas de negocio) y `rh`; el núcleo está siempre. Lo nuevo de un módulo lleva su marca: `modulo` en los tipos de `crear.js` y en los elementos de `AT.editorInsertar`, clases `.m-negocio`/`.m-rh` en HTML (base.css las oculta con `sin-<módulo>` en `<html>`); barra.js y buscar.js preguntan a `AT.perfil`. Sin perfil, `inicio.html` manda a `entrar.html` (asistente de 2 pasos porque hay un solo perfil; `?editar`, restaurar respaldo); con perfil, `entrar.html` manda al Inicio salvo con `?editar`. `base.js` no marca la visita en `entrar.html`. En las pruebas, `pagina()` siembra un negocio con el módulo de negocio; `perfil:false` deja el navegador sin espacio. Prueba: `22-entrar.js`.
- **Páginas de bienvenida** (sin barra lateral, `landing.js`, `landing.css`): `index.html` es la de negocios (carga `base.js`, `bloques.js`, `pagos.js`, `negocio.js`, `precio.js` y `negocio.css` para dibujar una página de ejemplo, un plan de pagos y la calculadora de precio para probar; `base.js` no marca la visita con `data-pagina="bienvenida"`). Si el navegador ya tiene datos con el prefijo `aprende-tecnologia:` (base.js marca `aprende-tecnologia:visita`), `landing.js` manda a `inicio.html` antes de pintar, salvo con `?conoce`. «Guárdalo en tu espacio» deja el plan en `sessionStorage` (`onebook:pagos-bienvenida`) y abre `inicio.html#guardar-pagos`, donde `crear.js` lo limpia y lo guarda como documento. El manifiesto abre la app instalada en `inicio.html`, y `inicio.html#crear` abre la ventana de Crear. Prueba: `19-landing.js`.
- **Rutas de archivos**: todas las páginas viven en la raíz (`AT.rutas.raiz` es ''); los `href` guardados (enlaces `cita`) son relativos a la raíz.
- **Service worker** (`sw.js`): red primero y copia para usar sin conexión. **Al agregar o quitar cualquier archivo del sitio hay que actualizar `ARCHIVOS` y subir `VERSION`**; `pruebas/6-app.js` falla si falta alguno (excluye `.claude/`, `pruebas/`, `herramientas/`, `.md` y `.txt`).
- **Para correr y manejar el sitio** (servirlo, abrir páginas, capturas, pruebas): skill `run-onelearn` (`.claude/skills/run-onelearn/`).

## Convenciones

- CSS: todos los tamaños en `rem`; colores solo con los tokens de `assets/css/base.css`, que tienen cuatro variantes (claro, oscuro, alto contraste claro y oscuro); sombras con `--sh-1` y `--sh-2`. Ancho: la Ayuda usa `--page-w` (columna de lectura) y las páginas de trabajo (`documento`, `inicio`) `--app-w`, más ancho en escritorio; `doc.anchoCompleto` («Ancho completo» en «⋯») pone `.doc-completo` en `<html>`, y Lectura ofrece `ancho` estrecho, normal, amplio o completo. Las pruebas auditan contraste WCAG (4.5:1, o 7:1 en alto contraste) y desbordes horizontales en varios anchos, tamaños de letra y fuentes (incluida OpenDyslexic).
- Accesibilidad: patrones ARIA (pestañas, barra de herramientas con flechas, combobox, `aria-disabled` en lugar de `disabled` para no perder el foco), manejo explícito del foco y atajos que se ignoran mientras se escribe.
- Cada hito trae su archivo de pruebas `pruebas/N-nombre.js` usando `lib.js` (`prueba`, `pagina`, `listo`, `revisar`). En pruebas del editor, deja una pausa breve después de teclas de movimiento o selección antes de un atajo (ProseMirror lee la selección del DOM de forma asíncrona).
