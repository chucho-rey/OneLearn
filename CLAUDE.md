# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Proyecto

OneBook (antes OneLearn): sitio estático en español (es-MX) publicado con GitHub Pages en `https://chucho-rey.github.io/OneLearn/` (rama `main`; el repositorio y la dirección conservan el nombre viejo por ahora). Es un espacio de trabajo de **bloques y plantillas** enfocado en negocios (pagos, cobros, inventario), que conserva las lecciones de tecnología y los documentos de estudio de OneLearn (libretas, apuntes, tesis); todo se guarda solo en el navegador. Local es gratis; la nube será de pago (F9). Todo el texto de la interfaz, los comentarios del código y los mensajes de commit van en español. El plan, las características y el roadmap viven en Notion (página «OneBook», con «OneBook: plan para pivotear» y la base «Roadmap», área OneBook, fases F1 a F10: F1 a F7 hechas (F3 pestañas y navegación, F4 bloques de la tienda, F5 plantillas, favoritas y papelera, sin páginas dentro de páginas, por decisión del 24 de noviembre de 2026, F6 bases de datos y vistas, F7 inventario, reportes y «Mi negocio»); siguen F8 pedidos al Cedis, F9 cuentas y nube, F10 escuelas; ahí están las decisiones: primer giro, tienda o comercio pequeño; sin empleados por ahora; solo MXN): es la fuente de información del equipo; al terminar un hito, actualiza ahí su estado. Las claves internas conservan el nombre viejo a propósito (prefijo `aprende-tecnologia:`, base `onelearn`, cachés `onelearn-`): cambiarlas borraría los datos de quien ya usa la app. Los respaldos se escriben con `app:'OneBook'` y se aceptan también los de `app:'OneLearn'`. El `README.md` describe el estado técnico actual.

## Comandos

No hay paso de compilación para publicar: se abre `index.html` o se sirve la carpeta con cualquier servidor estático. `index.html` es la página de bienvenida (landing) y el Inicio de la app es `inicio.html`; las pruebas entran por `inicio.html`.

Pruebas (Playwright, en `pruebas/`):

```
cd pruebas
npm install && npx playwright install chromium   # la primera vez, en una máquina propia
npm test                      # todas (node todas.js)
node todas.js 3 10            # solo los archivos 3-*.js y 10-*.js
node 9-editor.js              # un solo archivo
DETALLE=1 node 2-lectura.js   # muestra también lo que pasa
```

En el contenedor de Claude Code, Playwright está instalado globalmente: anteponer `NODE_PATH=/opt/node-tools/node_modules`. La suite completa tarda unos 4 minutos; conviene correrla en segundo plano.

Tiptap (solo al cambiar su versión): `cd herramientas/tiptap && npm install && npm run compilar` regenera `assets/vendor/tiptap.min.js` y `tiptap-LICENSE.txt`. Las versiones están fijadas en su `package.json`. KaTeX igual: `cd herramientas/katex && npm install && npm run copiar` (y actualizar la lista de sus fuentes en `sw.js`). docx y Paged.js (exportar): `cd herramientas/exportar && npm install && npm run copiar` regenera `assets/vendor/docx.min.js` (solo lo que importa `entrada.js`), `paged.min.js` y `exportar-LICENSE.txt`.

## Arquitectura

- **Scripts clásicos con un espacio global `window.AT`**, sin módulos ES ni bundler (para que funcione con `file://`). El orden de los `<script>` importa y está documentado en el README; cada página (`index.html`, `documento.html`, `lecciones/*.html`) lista los suyos. `ajustes.js` va en el `<head>` y aplica tema, contraste, tamaño, etc. antes de pintar.
- **Formato de bloques** (`assets/js/bloques.js`): lecciones y documentos son el mismo JSON `{formato, tipo, id, titulo, icono, props, contenido}`, donde `contenido` es JSON de Tiptap/ProseMirror. Cada bloque de primer nivel tiene `attrs.id` fijo (ancla de marcadores y citas; no cambiarlo en lecciones publicadas). `bloques.js` lo dibuja sin `innerHTML` con datos del documento y filtra enlaces (`hrefSeguro`). El editor (`editor.js`) define los mismos tipos de bloque como nodos de Tiptap; un tipo nuevo debe agregarse en ambos lados (y en el Markdown de `documento.js` y el texto de `bloques.js`).
- **Lecciones** (`lecciones/<id>.html`): el contenido es un `<script type="application/json" id="documento">`; cada laboratorio es un bloque `laboratorio` + `<template data-lab="nombre">` + `AT.labs['nombre']=function(raiz){}` en `<id>.js`. El `id` debe coincidir con `assets/js/catalogo.js` y con `data-leccion` del `<body>`. Hay 46 lecciones publicadas (45 de tecnología y «Cómo funciona OneBook», el primer grupo, que explica cómo usar el sitio; actualízala cuando agregues funciones visibles; las lecciones son del módulo estudio); las que tienen `id` y título pero no `archivo` salen como «Pronto». Piezas comunes para laboratorios: `AT.elegir(sel, fn)` en `base.js` y las clases `.kpis`, `.barras`/`.br`, `.msg`, `.campo` en `base.css`; los estilos propios van en `lecciones/<id>.css`. Toda lección nueva necesita sus comprobaciones en `pruebas/comprobaciones.js` (las usa `13-temas.js`). Los textos de los laboratorios que vienen del estudiante se muestran con `textContent` o `esc()`.
- **Tesis** (`crear.js` con `academico:true`, `fuentes.js`, `autoria.js`, `piezas.js`, `proteger.js`, plan en `docs/tesis.md`): las fuentes (`doc.fuentes`) y el registro de autoría (`doc.autoria`, solo números y fechas) viven en el documento. Nodos propios en `editor.js` y `bloques.js`: `referencia` (en línea), `bibliografia` y `declaracion`; el formato es APA 7 en español (`AT.fuentes.referencia` da trozos `{t, i}` para pintar o pasar a Markdown). `piezas.js` agrega figuras, tablas numeradas, ecuaciones y fórmulas (KaTeX en `assets/vendor/katex`, cargado al vuelo), notas al pie, índices de figuras y tablas y referencias cruzadas: registra sus nodos con `AT.editorExtensiones`/`AT.editorInsertar`, su dibujo con `AT.bloques.registrar` y su Markdown con `AT.piezas.md`, sin tocar editor.js ni bloques.js. Figuras, tablas y ecuaciones llevan `attrs.clave` única (la cuida el plugin de ids), destino de `refCruzada`. `proteger.js` es el botón «Respaldo» (copia descargable y copia automática en un archivo). Entregar (T4): `entrega.js` (formato `doc.formato`, `partes(doc)` = portada, preliminares y cuerpo, revisión previa, entregas en `doc.autoria.entregas`), `imprimir.html`/`imprimir.js` (PDF con Paged.js; la hoja del papel se arma en JS y los números de página se fijan página por página) y `exportar-docx.js` (DOCX con docx; leyendas con número escrito y estilos `LeyendaFigura`/`LeyendaTabla` para los índices). Citas en IEEE con `doc.formato.estilo`; `AT.fuentes.cita(attrs, fuentes, doc)` recibe el documento para el estilo y la numeración. La autoría es el eje: cualquier herramienta nueva de la tesis debe respetar el registro y la constancia. Pruebas: `17-tesis.js`, `18-piezas.js` y `20-entregar.js` (revisa el DOCX abriendo el ZIP con zlib).
- **Bloques de la tienda** (fase F4: `negocio.js` + `caja.js` corte de caja, `fiado.js`, `gastos.js` con «Generar mes», `venta.js` nota de venta con folio, `precio.js` calculadora de precio (también en `index.html`) y `porpagar.js` cuentas por pagar; se cargan después de `pagos.js` en documento.html e imprimir.html): un bloque nuevo se define con `AT.negocio.bloque(nombre, {etiqueta, def, filas, editar, resultado, leer, refrescar, acciones, texto, md, insertar, foco})`, que registra el nodo de Tiptap (atómico, un atributo JSON por clave de `def`), su dibujo, texto y Markdown, y su entrada en «/» con `modulo:'negocio'`; agrega el tipo a `AT.editorConId`. El HTML de `editar`/`leer` enlaza campos con `data-k="ruta.de.campo"` (`data-fecha` en casillas guarda la fecha; `data-repintar` repinta al cambiar) y botones con `data-acc` (`agregar`/`quitar` con `data-lista`/`data-i` ya existen; `data-enter` en un campo dispara una acción). `filas` da la forma de cada fila y no debe usar datos al azar (también completa lo guardado). Dinero: `AT.negocio.centavos`, `dinero(c, signo)` y `monto(c, signo)` (negativos con «−» y `.neg` en rojo). Folios: `AT.folio(prefijo)` en base.js (`aprende-tecnologia:folios`, entra en el respaldo). Estilos: lectura y formulario (`.nb-f`) en `negocio.css`, papel en `imprimir.js`. En las pruebas, Tiptap enfoca en el siguiente cuadro: espera el foco en `.ProseMirror` antes de teclear. Prueba: `24-tienda.js`.
- **Plantillas, favoritas y papelera** (fase F5; no hay páginas dentro de páginas, a propósito): `crear.js` es la galería (cada tipo de `AT.tiposDoc` tiene `cat` negocio|finanzas|estudio|general y `trae`; `PAQUETES` por giro; «Mis plantillas» en `AT.datos.plantillas`). `AT.crear.guardarPlantilla(doc, {nombre, desc, vaciar})` usa `VACIAR` por tipo de bloque y `desdePlantilla` usa `AL_CREAR` (fecha, folio, mes): un bloque nuevo con datos del día o anotados debe agregarse ahí. `datos.js` va en la versión 2 de la base con los almacenes `plantillas` (en el respaldo) y `papelera` (`AT.datos.papelera`: mover, restaurar, eliminar, vaciar; 30 días). Favorita: `doc.favorito`, se guarda con `conservarFecha`. Papelera en `respaldo.js` (`AT.papelera.abrir`, `[data-papelera]`). Inicio: acciones rápidas con `documento.html#agregar=<bloque>` (evento `onebook:agregar`, lo atiende `negocio.js`) y «Prepara tu negocio» (`aprende-tecnologia:prepara`). Prueba: `25-plantillas.js`.
- **Bases de datos** (fase F6: `bases.js` motor sin interfaz, `basedatos.js` el bloque, `bases.css`; en documento.html e imprimir.html después de `porpagar.js`): base `{id, nombre, doc, columnas, vistas}` y fila `{id, base, v:{idColumna: valor}, orden}` en los almacenes `bases` y `filas` (índice `base`; `AT.datos.filas.deBase`), versión 3 de la base. `AT.bases` guarda en memoria lo leído (`cargar` trae también las bases relacionadas), calcula (`valor`, `texto`, fórmulas con `compilar`, sin eval), filtra, ordena, agrupa, totaliza, lee y escribe CSV, y avisa los cambios (`AT.bases.on`; entre pestañas, por `AT.datos.on`). Tipos y su forma en el README; la primera columna es el nombre. El bloque `basedatos` guarda `{base, vista}` o `{semilla}` (plantillas, duplicar, tus plantillas): la base se crea al abrirlo (`AT.bases.crear`, una vez por bloque). `imprimir.js` llama `AT.bases.precargar` antes de paginar. El importador de Bases unificadas está en `datos.js` (`importar` con `app:'bases-unificadas'`). En las pruebas, un elemento `.vh` dentro de una tabla con scroll necesita un ancestro posicionado (`.bd-scroll` lo es). Prueba: `26-bases.js`.
- **Inventario, reportes y «Mi negocio»** (fase F7; `inventario.js`, `factura.js`, `reporte.js`, `indicadores.js`, en documento.html, imprimir.html e inicio.html después de `basedatos.js`): bases con `rol` (productos, movimientos, compras, gastos, presupuesto), una por espacio: `AT.inventario.asegurar(doc, roles)` las busca o crea (ids de columna fijos: `p-*`, `m-*`, `c-*`, `g-*`, `r-*`; el resto del código los usa) y `base(rol)` es lo que usa un bloque `basedatos` con `semilla:{rol, vista}`. La nota de venta (`venta.js`) liga conceptos a productos (`prod`) y `inventario.js` sincroniza sus movimientos «Venta» al guardarse una página (`AT.datos.on`, `m-origen` venta:<página>:<bloque>:<i>), los quita antes de la papelera (`documento.js`) y concilia todo al abrir. Fórmulas con comparaciones, texto y funciones en `bases.js` (`compilar` da `fn.tipo` numero|texto|logico); formato condicional `col.colores` y `B.tonoCelda`. Bloques propios con nodo de Tiptap (atributo `cfg` JSON): `reporte` (cfg con `base` o `rol`, `pbase` o `prol` para presupuesto; `AT.reporte.calcular`), `indicadores` (items de reporte) y `vencimientos` (dias); en el Inicio se dibujan vivos (`data-pagina` inicio) y al imprimir como papel. Lo que un bloque necesita leído antes de imprimir va en `AT.bases.precargas`. Para abrir una ventana desde un clic dentro de un bloque usa `setTimeout` (quien cierra ventanas al hacer clic fuera la cerraría). Imprimir acepta hoja horizontal (`doc.formato.orientacion`). Inicio de negocio: «Mi negocio» = documento `d-minegocio` (se crea solo una vez, solo si `AT.datos.documentos.leer` no lo encuentra). Pruebas: `28-inventario.js`, `29-reportes.js`, `30-indicadores.js`, `31-minegocio.js` (espera «Guardado» antes de recargar una página que acabas de cambiar).
- **Plan de pagos** (`pagos.js`, bloque `pagos` en cualquier documento; estilos de lectura en `negocio.css`; `AT.pagos.vista(attrs, {editable, marcar})` dibuja la vista de lectura): `attrs` {titulo, modo plazos|cuota, monto, pagos, cuota, frecuencia, inicio, pagados:{n: fecha}}; `AT.pagos.calcular` trabaja en centavos y el último pago absorbe el redondeo. Al leer, marcar un pago cambia el bloque en `AT.docActual` (por su `attrs.id`) y guarda con `AT.docCambio`. Prueba: `21-pagos.js`.
- **Datos** (`datos.js`, `AT.datos`): documentos, notas y marcadores en IndexedDB (base `onelearn`), con `localStorage` como respaldo si no hay IndexedDB. Las notas se escriben primero en un diario de `localStorage` (`aprende-tecnologia:apuntes:<id>`) y luego en IndexedDB. Avance y ajustes siguen en `localStorage` (prefijo `aprende-tecnologia:`). Los cambios se avisan con `AT.datos.on` y entre pestañas con BroadcastChannel.
- **«Cómo está hecho OneBook»** (`acerca.html`, `data-pagina="acerca"`): página para estudiantes de programación que describe la arquitectura y las tecnologías, en el formato de bloques. Si cambias la arquitectura, las versiones o las cifras de pruebas, actualiza también su JSON. La búsqueda la incluye por `PAGINAS` en `buscar.js`.
- **Rutas de aprendizaje** (`rutas.html`, `assets/js/rutas.js`, `data-pagina="rutas"`): `AT.caminos` en `catalogo.js` ordena lecciones y proyectos por módulos (en código se llama «caminos» porque `AT.rutas` son las rutas de archivos). El avance lo calcula `AT.avance.camino`; `AT.caminoDe(id)` (base.js) dice el módulo de una lección, y `barra.js` agrega el aviso de ruta al final de la lección. La ruta «Redes y sistemas» está completa: 27 lecciones en 6 módulos y 2 proyectos. Prueba: `15-rutas.js`.
- **Simulador de red** (`assets/js/red.js` y `assets/css/red.css`, en las lecciones que lo usan, antes de `<id>.js`): `AT.ip` (IPv4/IPv6, subredes, EUI-64) y `AT.red.crear(contenedor, topologia)`, que dibuja la red en SVG y calcula el camino de un paquete (`camino`, rutas estáticas u OSPF con `dinamico`).
- **Terminal simulada** (`assets/js/terminal.js` y `assets/css/terminal.css`, cargados solo en las lecciones que la usan, antes de `<id>.js`): `AT.terminal(contenedor, {archivos, preparar, tareas, sugerencias, clave, listas, host})`. Es un shell en memoria (lexer, parser, tuberías con promesas) con sistema de archivos, usuarios, permisos, procesos, servicios, apt, nano, scripts y cron. Simula la red (`s.red`: rutas, vecinos, DNS, `s.red.web[ip|puerto]` para sitios y apps de ejemplo) y otros equipos con `remotos:[{op, preparar}]`, a los que se entra con ssh; cada uno tiene sus servicios (`local:true` escucha solo en 127.0.0.1), `ufw` y nginx (`AT.terminal.util.instalar(s,'nginx')`). `contenedores.js` agrega `docker` solo en esa lección. Los ejercicios son `{id, texto, pista, ok(sis, ultimo, t)}`; se guardan en `aprende-tecnologia:terminal` y entran en el respaldo. Comandos nuevos: `AT.terminal.comando(nombres, meta, fn)`. En `comprobaciones.js`, `sesion()` resuelve los ejercicios tecleando. Prueba: `16-terminal.js`.
- **Proyectos** (`proyectos/`, `assets/js/proyecto.js`): casos prácticos por fases. Cada proyecto es `proyectos/<id>.html` con su JSON en `<script id="proyecto">` (fases con contenido en el formato de bloques, tareas y entregable) y una entrada en `AT.proyectos` (`catalogo.js`) cuyo total de tareas y fases debe coincidir (lo revisa `14-proyectos.js`). Si tiene diagramas interactivos, van como laboratorios en `proyectos/<id>.js` y `.css` (ver `red-oficina`). El avance está en `AT.proyectosAvance` (`base.js`, localStorage) y entra en el respaldo.
- **Pestañas** (`app.html`, `pestanas.js`, `pestanas.css`, fase F3): el contenedor pone cada página en un iframe; `base.js` (si `window.parent.AT.pestanas` existe) marca `AT.enPestana`/`.en-pestanas`, avisa título y dirección (`AT.pestanas.cambio`), pasa atajos (`AT.pestanas.atajo`) y abre en pestaña nueva los enlaces con clic central o Ctrl/Cmd+clic. `AT.pestanas`: abrir, abrible, cerrar, activar, descargar, lista. `app.html` es el `start_url` del manifiesto y no se abre dentro de sí mismo. `documento.js`: `AT.docGuardarYa` (lo usa el contenedor antes de cerrar o descargar) y el bloqueo de la misma página en dos pestañas (`onebook-documentos`). Botón Atrás: `AT.alAtras(fn)` (CloseWatcher) para paneles que no son `<dialog>`. Prueba: `23-pestanas.js` (para elementos dentro de una pestaña oculta, `waitForSelector` con `state:'attached'`).
- **Perfiles y módulos** (`perfil.js` en el `<head>` de todas las páginas después de `ajustes.js`, `entrar.html`/`entrar.js`/`entrar.css`, fase F2): `AT.perfil` con `aprende-tecnologia:perfil` = {perfil negocio|personal|estudio, modulos, nombre, negocio:{nombre, giro, telefono}, creado, migrado}. `AT.perfil.tiene(modulo)` decide qué se ve (sin perfil, todo). Módulos: `negocio` (plan de pagos, bloques de la tienda y plantillas de negocio) y `estudio` (lecciones, rutas, proyectos, libretas, apuntes, tesis, herramientas académicas). Lo nuevo de un módulo lleva su marca: `modulo` en los tipos de `crear.js` y en los elementos de `AT.editorInsertar`, clases `.m-estudio`/`.m-negocio`/`.m-sin-estudio` en HTML (base.css las oculta con `con-`/`sin-<módulo>` en `<html>`); barra.js y buscar.js preguntan a `AT.perfil`. Sin perfil, `inicio.html` manda a `entrar.html` (asistente de 3 pasos; `?perfil=`, `?editar`, restaurar respaldo); con perfil, `entrar.html` manda al Inicio salvo con `?editar`. Quien tenía datos de OneLearn migra a estudio con estudio y negocio. `base.js` no marca la visita en `entrar.html`. En las pruebas, `pagina()` siembra ese perfil migrado; `perfil:false` deja el navegador sin espacio. Prueba: `22-entrar.js`.
- **Páginas de bienvenida** (sin barra lateral, `landing.js`, `landing.css`): `index.html` es la de negocios (carga `base.js`, `bloques.js`, `pagos.js`, `negocio.js`, `precio.js` y `negocio.css` para dibujar una página de ejemplo, un plan de pagos y la calculadora de precio para probar; `base.js` no marca la visita con `data-pagina="bienvenida"`) y `estudiantes.html` la de estudiantes (la anterior). Si el navegador ya tiene datos con el prefijo `aprende-tecnologia:` (base.js marca `aprende-tecnologia:visita`), `landing.js` manda a `inicio.html` antes de pintar, salvo con `?conoce`. «Guárdalo en tu espacio» deja el plan en `sessionStorage` (`onebook:pagos-bienvenida`) y abre `inicio.html#guardar-pagos`, donde `crear.js` lo limpia y lo guarda como documento. El manifiesto abre la app instalada en `inicio.html`, y `inicio.html#crear` abre la ventana de Crear. Prueba: `19-landing.js`.
- **Rutas de archivos**: `inicio` (`inicio.html`), `documento`, `acerca` y `rutas` viven en la raíz; las lecciones en `lecciones/` y los proyectos en `proyectos/` (desde ahí `AT.rutas.lecciones` es `../lecciones/`). `AT.rutas.raiz` da el prefijo correcto; los `href` guardados (citas, marcadores) son relativos a la raíz.
- **Service worker** (`sw.js`): red primero y copia para usar sin conexión. **Al agregar o quitar cualquier archivo del sitio hay que actualizar `ARCHIVOS` y subir `VERSION`**; `pruebas/6-app.js` falla si falta alguno (excluye `.claude/`, `pruebas/`, `herramientas/`, `.md` y `.txt`).
- **Para correr y manejar el sitio** (servirlo, abrir páginas, escribir en la terminal de un laboratorio, capturas): skill `run-onelearn` (`.claude/skills/run-onelearn/`).

## Convenciones

- CSS: todos los tamaños en `rem`; colores solo con los tokens de `assets/css/base.css`, que tienen cuatro variantes (claro, oscuro, alto contraste claro y oscuro); sombras con `--sh-1` y `--sh-2`. Ancho: las lecciones usan `--page-w` (columna de lectura) y las páginas de trabajo (`documento`, `inicio`) `--app-w`, más ancho en escritorio; `doc.anchoCompleto` («Ancho completo» en «⋯») pone `.doc-completo` en `<html>`, y Lectura ofrece `ancho` estrecho, normal, amplio o completo. Las pruebas auditan contraste WCAG (4.5:1, o 7:1 en alto contraste) y desbordes horizontales en varios anchos, tamaños de letra y fuentes (incluida OpenDyslexic).
- Accesibilidad: patrones ARIA (pestañas, barra de herramientas con flechas, combobox, `aria-disabled` en lugar de `disabled` para no perder el foco), manejo explícito del foco y atajos que se ignoran mientras se escribe.
- Cada hito trae su archivo de pruebas `pruebas/N-nombre.js` usando `lib.js` (`prueba`, `pagina`, `listo`, `revisar`). En pruebas del editor, deja una pausa breve después de teclas de movimiento o selección antes de un atajo (ProseMirror lee la selección del DOM de forma asíncrona).
